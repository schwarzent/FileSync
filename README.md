# FileSync

Windows 文件同步工具，支持局域网直连和本机已登录的 OneDrive 中继。中文界面，手动预览并执行同步，保留版本，可选完整备份。

## 开始使用

1. 将 Windows 运行包解压到可写的文件夹，在两台电脑上分别运行 `FileSync.exe`，浏览器会自动打开 `http://127.0.0.1:5378`。保留程序窗口，按 Ctrl+C 退出。
2. 在「局域网设备」生成一次性配对邀请，在另一台电脑粘贴邀请并配对。邀请 5 分钟有效。
3. 在来源电脑发布「本机源文件夹」。在另一台电脑新建同步任务，选择远端设备、远端源文件夹和本机目标文件夹，并选择单向或双向同步。文件夹旁的「浏览」打开 Windows 系统选择框，可在地址栏粘贴路径，也可直接在表单输入路径。双向同步需先在远端共享设置中启用「允许配对设备双向写入」。
4. 点击「预览同步」，检查新增、更新与删除，点击「执行同步」。可在编辑任务时启用完整备份并选择备份位置。

在「设置 → 同步任务配置备份」点击「导出所有任务」，将全部局域网和 OneDrive 任务保存为一个 JSON 文件。通过「导入配置文件」选择备份，预览新增、更新和相同任务的数量后导入，即可恢复路径、同步方式、过滤规则和完整备份设置。同编号任务更新，其他已有任务保留，重复导入不会创建副本。配置备份不包含资料文件、版本记录或设备配对身份；换机恢复局域网任务需先与原设备配对。

默认是 **单向：远端源文件夹 → 本机目标文件夹**，目标将与来源一致，本机独有文件会移入版本库。可选 **双向：远端文件夹 ↔ 本机文件夹**，首次合并两端独有文件，后续根据上次成功同步记录传播修改和删除。已有任务默认保持单向。支持 Windows 10/11 x64，不需要预装 .NET、Go 或其他运行环境。

双向模式在预览中分别列出两端变化。同一路径两端内容不同且均已修改（含首次同名不同内容）、一端删除且另一端修改、目录删除与子项新增等情况会列出冲突。可逐项保留本机或远端，勾选多项后批量选择，或直接全部保留本机／远端；全选覆盖所有分页，批量选择后仍可逐项调整。应用选择后查看最终预览，再执行同步。目录冲突按整个目录及子项处理；选择已删除的一端会传播删除。相同内容及目录的修改时间取两端较晚值；不依赖设备时钟判断内容覆盖方向。同步关系由发起端任务维护，请在同一任务中执行后续同步。

共享和同步任务均可设置「忽略规则」，每行一条相对路径，例如 `.git/`、`node_modules/`、`/build/`、`**/cache/`、`*.tmp`。支持 `*`、`**`、`?` 和以 `#` 开头的注释，使用 `/` 分隔；暂不支持 `!` 反向规则或 `[]` 字符组。共享与任务规则合并后同时用于两端；忽略目录不遍历内部文件，不参与比较、传输或备份，已有内容保留。包含忽略子项的父目录也会保留。两端请使用同一版本，以支持带过滤规则的文件清单请求。

## 文件记录仓库（仅元数据）

1. 打开「文件记录仓库 → 新建记录仓库」，选择本机资料文件夹。另一台电脑选择「加入局域网仓库」并选中第一台的仓库；也可在两台电脑上选择同一个 OneDrive 云端文件夹作为「记录文件夹」，等待第一台的仓库信息下载后再加入。
2. 各端点击「生成本机记录」。程序读取本机文件计算 SHA-256，记录相对路径、大小、原始创建及修改时间、设备和本次修改列表，仅保存 JSON，不复制资料文件。局域网点击「交换局域网记录」；OneDrive 只需等待记录文件同步。
3. 点击「仅比对记录」，查看两端独有文件、原始修改时间较新的一端、内容及结构冲突，以及各设备本次记录中的修改。比较只读取已保存记录，不扫描资料，也不要求另一台电脑在线。资料更新后需重新生成记录。

记录仓库可以独立使用，无需先创建同步任务或上传全部资料。文件内容仍保留在原电脑；实际文件传输继续使用原同步任务的预览和执行。记录文件用于比较，无法独立恢复文件内容。记录位置在界面显示，快照及父哈希保留在 `.filesync-records/` 中；未选择记录文件夹时保存在本机程序数据目录的 `records/<仓库编号>/`。

## OneDrive 远程同步

1. 两台电脑登录并启用 Windows OneDrive 客户端。在 FileSync 点击「新建同步任务 → OneDrive 远程同步」，分别选择本机资料文件夹，以及 OneDrive 内专门用于中继的子文件夹。两端的中继路径可以不同，但必须对应同一个云端文件夹；本机资料与中继路径不能相互包含。无需局域网配对或另行输入云端凭据。
2. 来源端点击「发布到 OneDrive」。仓库中保存原文件名、原目录和原始文件内容，不加密。程序自动记录提交设备、提交编号、上传时间，以及文件的创建时间、修改时间、大小和 SHA-256。仓库已有的普通文件会在首次提交时一同纳入记录。此操作只确认本机仓库写入完成；继续等待 OneDrive 客户端显示上传完成。
3. 另一端等待 OneDrive 下载后点击「预览接收」，查看变化，再执行。程序检查清单及全部内容的哈希，暂存并验证后才修改本机资料，最后自底向上恢复目录时间，重新扫描核对内容、创建时间和修改时间。清单或内容尚未到齐、被损坏时会明确报错，等待客户端下载完成后重新预览。

OneDrive 任务按清单中的**原始修改时间**比较版本，不使用上传时间、下载时间或发布时间。文件内容不同时，保留修改时间较新的版本；时间相同但内容不同、类型不同或名称大小写冲突时，需要选择本机或远端版本。两端设备时钟需准确。相同修改时间及内容的文件采用中继记录的创建时间；目录采用修改时间较晚一端的元数据，空目标的根目录使用来源元数据。

两端均可发布和接收，按顺序操作，避免同时发布。发布时也会合并当前仓库中的较新版本和独有文件。接收后仍有本机较新版本或独有资料时，在该端再次发布，另一端接收后可取得这些资料。OneDrive 模式保留独有文件，**不自动传播删除**；接收支持版本记录、撤销、中断恢复及完整备份。局域网任务的原有单向和双向行为不变。

任务支持通用「忽略规则」，还可分别设置「仅上传时忽略」和「仅拉取时忽略」，规则语法相同。上传忽略项不会从仓库移除，拉取忽略项不会覆盖本机已有内容。两台电脑可以使用各自的规则，仓库记录保留完整文件清单。

点击任务上的「仓库历史」可查看两端共享的连续提交记录，按文件路径筛选，并查看每项修改前后的时间、大小、哈希和 UTF-8 文本内容。二进制文件显示版本元数据，原始内容仍完整保存。「版本记录」继续显示本机接收、撤销和恢复记录。

仓库示例：

```text
OneDrive/共享资料/
  文档.txt                         # 可直接打开的原始文件
  项目/                           # 原始目录
  .filesync-repo/
    history.json                  # 格式化共享日志，含修改前后元数据
    current.json                  # 当前提交编号和 SHA-256
    snapshots/<编号>.json         # 每次提交的完整清单、父提交、修改列表
    objects/<SHA-256>             # 不加密的历史文件内容，相同内容只保存一份
```

`history.json` 中的 `sequence` 表示提交顺序，`uploadedUtc` 为提交到本机 OneDrive 目录的 UTC 时间，`publisher` 为设备名称；每项 `changes` 包含路径、变化类型、修改前后的创建时间、修改时间、大小和哈希。客户端完成云端上传的时刻由 OneDrive 管理，工具不将本机写入误报为云端完成。

`.filesync-repo` 是仓库记录目录，工作区不能使用这一同名顶层目录。请通过工具提交工作区修改，保持仓库副本和历史内容完整；直接修改仓库文件会在校验时明确报错。目录哈希包含目录元数据及按名称排序的子项哈希，空目录及根目录也有哈希。旧提交、历史内容及中断材料保留，不自动清理。

发布中断后，「仓库历史」会提供「恢复中断的发布」，根据已校验的历史内容完成本次提交。恢复前若发现仓库内存在未记录的外部改动，会停止并保留这些内容。云端正在同步时应先等待完成。旧版 `current.json`／`snapshots`／`objects` 中继保留原状；使用新版普通文件仓库时请另外选择文件夹。

仅联机文件在读取时由 OneDrive 下载；OneDrive 离线、暂停或空间不足等错误需在客户端处理。同步状态含义见 [微软 OneDrive 图标说明](https://support.microsoft.com/en-us/onedrive/what-do-the-onedrive-icons-mean)。

## 版本与恢复

- 文件比较包含 SHA-256 与 UTC 修改时间；OneDrive 清单额外记录并校验创建时间。空目录、目录与根文件夹的时间在最后恢复，避免变成传输时间。
- 「版本记录」可查看增删改，并逐次撤销最近完成的同步。双向任务会同时撤销两端，要求两台设备在线；任一端后续修改会阻止撤销。接收设备也会保留本机版本记录，在接收端直接撤销仅恢复该设备。
- 中断的同步显示恢复操作，恢复完成前不执行新同步。双向中断请在发起端恢复，以还原两端。两端无法原子提交，网络断开或提交响应丢失会保留待恢复状态，不报告成功。传输和备份阶段可取消，应用文件修改时等待完成校验。
- 程序数据默认位于程序旁的 `.filesync`。该目录包含加密设备身份、配置、版本库和中断恢复材料，请保留。可选完整备份按每次同步单独存储。
- 版本与备份不自动清理。当前不提供文件内容自动合并或后台自动同步。

## 网络与安全

专用局域网使用 TCP `5379` 传输、UDP `5380` 发现设备；管理界面仅监听本机 TCP `5378`。需要在 Windows 防火墙的专用网络中允许 FileSync 与其通信组件。自动发现受网络广播策略影响，配对邀请使用所选本机 IPv4 地址。

设备间 TLS 1.2/1.3 加密，双方校验配对证书指纹；已发布文件夹默认仅允许配对设备读取，显式启用双向写入后才接受修改。写入事务绑定发起设备和共享，不接受任意远端绝对路径。请通过可信渠道交换邀请，并在两台设备上分别撤销不用的配对。身份由当前 Windows 用户 DPAPI 保护，复制数据目录到另一用户或电脑不会复制设备身份。

为保护同步范围，拒绝目录联接、符号链接、网络共享、磁盘根目录，以及相互包含的源、目标、中继、备份和程序数据路径。支持 OneDrive 使用的 Windows Cloud 占位文件，其他重解析点明确报错。支持中文、空格、空目录及文件/目录类型替换。

所有文件按固定 128 KiB 缓冲区流式处理，不启动文件监听器或自动同步。自动发现每 15 秒广播。应用空闲时不扫描文件夹。程序只在自己的数据目录提取通信组件，退出时关闭；不安装证书，不更改系统信任、代理或防火墙规则。

## 开发与验证

需要 .NET SDK 10 和 Go 1.27.2，PowerShell 7：

```powershell
./scripts/Start.ps1
./scripts/Test.ps1
./scripts/Publish.ps1
```

脚本支持 `-Dotnet`、`-Go` 指定可执行文件路径。后端测试使用项目内隔离目录，包含两实例真实 TLS 配对和文件同步，设置 60 秒硬超时。测试材料保留在 `.test-runs`，构建材料位于 `.artifacts`，均不进入 Git。

发布包使用英文路径：`README.md`、`ThirdPartyLicenses/`、`docs/`。界面与文档内容仍为中文，用户原有文件名称保持原样。

可执行文件参数：`--data <完整路径>`、`--ui-port <端口>`、`--port <端口>`、`--no-discovery`、`--no-browser`。默认数据目录无需手动指定；同一数据目录仅能运行一个实例。

实现说明见 [docs/DESIGN.md](docs/DESIGN.md)。验收记录见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。
