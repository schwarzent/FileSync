# FileSync

Windows 文件比较与同步工具。先交换轻量文件清单，离线查看两端差异并保存方案；局域网连接后，只传输和修改方案列出的文件。清单及方案可放在本机或 OneDrive，资料无需预先上传。

## 开始使用

1. 将 Windows 运行包解压到可写的文件夹，在两台电脑上分别运行 `FileSync.exe`，浏览器会自动打开 `http://127.0.0.1:5378`。保留程序窗口，按 Ctrl+C 退出。
2. 首页「清单与方案」点击「添加资料文件夹」，选择本机资料和清单保存位置。两端选择对应的同一个 OneDrive 记录文件夹，即可交换 JSON 记录；留空则只保存在本机。通过局域网交换时，先在「局域网设备」配对，再在另一端添加文件夹时选择加入已有仓库。邀请 5 分钟有效。
3. 两端分别点击「扫描并更新清单」。程序读取本机文件计算哈希，只保存路径、大小、创建和修改时间等记录。等待 OneDrive 同步记录，或点击「局域网交换清单」。交换不传输资料内容。
4. 点击「比较清单并制定方案」。无需对方在线，不重扫资料，即可查看两端独有项、修改时间较新的一端、冲突和本次记录变化。逐项选择采用哪端，或勾选后批量选择；默认「暂不处理」。
5. 点击「预览方案」，核对两个方向的新增、修改、删除及目录依赖，保存方案。方案写入记录目录，可随 OneDrive 交换，重启后仍可查看。
6. 局域网连接后，在对方点击「允许局域网执行」。从任一参与设备的「已保存方案」打开方案，点击「连接局域网并检查方案」，核对实际修改后「执行本方案」。只处理列出的路径，未选文件保留；选定文件已经改变时明确停止。执行与撤销记录显示在「版本记录」。

目录选择包含**生成清单时已记录的子项**，缺少的必需父目录会在预览中列明。采用不存在的一端会删除另一端对应项目。后来新增且未列入方案的子项不会被目录替换或删除连带移走，此时会明确停止该方案。未选文件内容及创建、修改时间保持原样；必要父目录和根目录会恢复本次检查时的时间。

点击「局域网共享权限」可关闭写入；该权限允许配对设备读取资料并提交写入事务，方案的实际执行仍逐项限制路径。所有操作均需手动发起。

「整目录同步」保留原有局域网单向、双向和 OneDrive **实际文件中继**功能。此页面会比较整个参与同步的目录；OneDrive 文件中继会上传实际资料及历史内容。仅做轻量比较和逐项计划时使用首页的「清单与方案」。

整目录任务使用方式：配对后共享来源文件夹，新建整目录任务并点击「比较整目录」；检查预览后点击「执行整目录同步」。文件夹旁的「浏览」使用 Windows 文件夹选择框，也可直接输入路径。

在「设置 → 整目录任务配置备份」点击「导出整目录任务」，将全部局域网和 OneDrive 任务保存为一个 JSON 文件。通过「导入整目录任务」选择备份，预览新增、更新和相同任务的数量后导入，即可恢复路径、同步方式、过滤规则和完整备份设置。同编号任务更新，其他已有任务保留，重复导入不会创建副本。配置备份不包含资料文件、版本记录或设备配对身份；换机恢复局域网任务需先与原设备配对。

默认是 **单向：远端源文件夹 → 本机目标文件夹**，目标将与来源一致，本机独有文件会移入版本库。可选 **双向：远端文件夹 ↔ 本机文件夹**，首次合并两端独有文件，后续根据上次成功同步记录传播修改和删除。已有任务默认保持单向。支持 Windows 10/11 x64，不需要预装 .NET、Go 或其他运行环境。

同一个本机资料文件夹可以同时用于局域网任务、OneDrive 任务及本机共享，无需移除已有任务。各任务保留独立配置和版本记录，手动依次执行；另一任务改变资料后，已有预览需重新生成。

双向模式在预览中分别列出两端变化。同一路径两端内容不同且均已修改（含首次同名不同内容）、一端删除且另一端修改、目录删除与子项新增等情况会列出冲突。可逐项保留本机或远端，勾选多项后批量选择，或直接全部保留本机／远端；全选覆盖所有分页，批量选择后仍可逐项调整。应用选择后查看最终预览，再执行同步。目录冲突按整个目录及子项处理；选择已删除的一端会传播删除。相同内容及目录的修改时间取两端较晚值；不依赖设备时钟判断内容覆盖方向。同步关系由发起端任务维护，请在同一任务中执行后续同步。

共享和同步任务均可设置「忽略规则」，每行一条相对路径，例如 `.git/`、`node_modules/`、`/build/`、`**/cache/`、`*.tmp`。支持 `*`、`**`、`?` 和以 `#` 开头的注释，使用 `/` 分隔；暂不支持 `!` 反向规则或 `[]` 字符组。共享与任务规则合并后同时用于两端；忽略目录不遍历内部文件，不参与比较、传输或备份，已有内容保留。包含忽略子项的父目录也会保留。两端请使用同一版本，以支持带过滤规则的文件清单请求。

## 清单与方案的保存方式

每个文件夹对应一个共同仓库编号，两台电脑各自使用自己的本机资料路径。另一台电脑可选择「加入局域网仓库」，或选择已经含有仓库信息的 OneDrive 记录文件夹。手动复制整个记录文件夹后也可选择该文件夹加入，无需联网。

清单及方案仅包含 UTF-8 JSON：`repository.json` 标识仓库，`heads/` 标识各设备最新记录，`snapshots/` 保存各次清单和父哈希，`plans/` 保存冻结双方清单引用和逐路径处理方向的方案。不保存文件内容对象。资料更新后手动扫描新清单；旧方案仍引用原清单，执行时检查相关文件。记录文件无法独立恢复资料内容。

记录位置在界面显示。选择记录文件夹时，内部文件保存在 `.filesync-records/`；留空时使用本机程序数据目录的 `records/<仓库编号>/`。OneDrive 同步的是此记录文件夹，实际文件在方案执行时通过局域网传输；两端均应使用本版程序。

## OneDrive 远程同步

1. 两台电脑登录并启用 Windows OneDrive 客户端。在 FileSync 点击「整目录同步 → 新建整目录任务 → OneDrive 文件中继」，分别选择本机资料文件夹，以及 OneDrive 内专门用于中继的子文件夹。两端的中继路径可以不同，但必须对应同一个云端文件夹；本机资料与中继路径不能相互包含。无需局域网配对或另行输入云端凭据。
2. 来源端点击「将资料写入 OneDrive」。仓库中保存原文件名、原目录和原始文件内容，不加密。程序自动记录提交设备、提交编号、上传时间，以及文件的创建时间、修改时间、大小和 SHA-256。仓库已有的普通文件会在首次提交时一同纳入记录。此操作只确认本机仓库写入完成；继续等待 OneDrive 客户端显示上传完成。
3. 另一端等待 OneDrive 下载后点击「预览接收资料」，查看变化，再执行。程序检查清单及全部内容的哈希，暂存并验证后才修改本机资料，最后自底向上恢复目录时间，重新扫描核对内容、创建时间和修改时间。清单或内容尚未到齐、被损坏时会明确报错，等待客户端下载完成后重新预览。

OneDrive 任务按清单中的**原始修改时间**比较版本，不使用上传时间、下载时间或发布时间。文件内容不同时，保留修改时间较新的版本；时间相同但内容不同、类型不同或名称大小写冲突时，需要选择本机或远端版本。两端设备时钟需准确。相同修改时间及内容的文件采用中继记录的创建时间；目录采用修改时间较晚一端的元数据，空目标的根目录使用来源元数据。

两端均可发布和接收，按顺序操作，避免同时发布。发布时也会合并当前仓库中的较新版本和独有文件。接收后仍有本机较新版本或独有资料时，在该端再次发布，另一端接收后可取得这些资料。OneDrive 模式保留独有文件，**不自动传播删除**；接收支持版本记录、撤销、中断恢复及完整备份。局域网任务的原有单向和双向行为不变。

任务支持通用「忽略规则」，还可分别设置「仅上传时忽略」和「仅拉取时忽略」，规则语法相同。上传忽略项不会从仓库移除，拉取忽略项不会覆盖本机已有内容。两台电脑可以使用各自的规则，仓库记录保留完整文件清单。

点击任务上的「文件中继历史」可查看两端共享的连续提交记录，按文件路径筛选，并查看每项修改前后的时间、大小、哈希和 UTF-8 文本内容。二进制文件显示版本元数据，原始内容仍完整保存。「版本记录」继续显示本机接收、撤销和恢复记录。

仓库示例：

```text
OneDrive/共享资料/
  文档.txt                         # 可直接打开的原始文件
  项目/                           # 原始目录
  .filesync-repo/
    history.json                  # 格式化共享日志，含修改前后元数据
    current.json                  # 当前提交编号和 SHA-256
    snapshots/<编号>.json         # 每次提交的完整清单、父提交、修改列表
    objects/<SHA-256>             # 不加密的历史文件内容，相同内容只保存一份
```

`history.json` 中的 `sequence` 表示提交顺序，`uploadedUtc` 为提交到本机 OneDrive 目录的 UTC 时间，`publisher` 为设备名称；每项 `changes` 包含路径、变化类型、修改前后的创建时间、修改时间、大小和哈希。客户端完成云端上传的时刻由 OneDrive 管理，工具不将本机写入误报为云端完成。

`.filesync-repo` 是仓库记录目录，工作区不能使用这一同名顶层目录。请通过工具提交工作区修改，保持仓库副本和历史内容完整；直接修改仓库文件会在校验时明确报错。目录哈希包含目录元数据及按名称排序的子项哈希，空目录及根目录也有哈希。旧提交、历史内容及中断材料保留，不自动清理。

发布中断后，「文件中继历史」会提供「继续完成中继写入」，根据已校验的历史内容完成本次提交。恢复前若发现仓库内存在未记录的外部改动，会停止并保留这些内容。云端正在同步时应先等待完成。旧版 `current.json`／`snapshots`／`objects` 中继保留原状；使用新版普通文件仓库时请另外选择文件夹。

仅联机文件在读取时由 OneDrive 下载；OneDrive 离线、暂停或空间不足等错误需在客户端处理。同步状态含义见 [微软 OneDrive 图标说明](https://support.microsoft.com/en-us/onedrive/what-do-the-onedrive-icons-mean)。

## 版本与恢复

- 文件比较包含 SHA-256 与 UTC 修改时间；OneDrive 清单额外记录并校验创建时间。空目录、目录与根文件夹的时间在最后恢复，避免变成传输时间。
- 「版本记录」可查看增删改，并逐次撤销最近完成的同步。双向任务会同时撤销两端，要求两台设备在线；任一端后续修改会阻止撤销。接收设备也会保留本机版本记录，在接收端直接撤销仅恢复该设备。
- 中断的同步显示恢复操作，恢复完成前不执行新同步。双向中断请在发起端恢复，以还原两端。两端无法原子提交，网络断开或提交响应丢失会保留待恢复状态，不报告成功。传输和备份阶段可取消，应用文件修改时等待完成校验。
- 程序数据默认位于程序旁的 `.filesync`。该目录包含加密设备身份、配置、版本库和中断恢复材料，请保留。可选完整备份按每次同步单独存储。
- 版本与备份不自动清理。当前不提供文件内容自动合并或后台自动同步。

## 网络与安全

专用局域网使用 TCP `5379` 传输、UDP `5380` 发现设备；管理界面仅监听本机 TCP `5378`。需要在 Windows 防火墙的专用网络中允许 FileSync 与其通信组件。自动发现受网络广播策略影响，配对邀请使用所选本机 IPv4 地址。

设备间 TLS 1.2/1.3 加密，双方校验配对证书指纹；已发布文件夹默认仅允许配对设备读取，显式启用双向写入后才接受修改。写入事务绑定发起设备和共享，不接受任意远端绝对路径。请通过可信渠道交换邀请，并在两台设备上分别撤销不用的配对。身份由当前 Windows 用户 DPAPI 保护，复制数据目录到另一用户或电脑不会复制设备身份。

为保护同步范围，拒绝目录联接、符号链接、网络共享和磁盘根目录。源和目标可复用完全相同的本机资料目录，不同资料目录不能相互嵌套；中继、备份和程序数据目录仍须与资料目录分开，不能相同或相互包含。支持 OneDrive 使用的 Windows Cloud 占位文件，其他重解析点明确报错。支持中文、空格、空目录及文件/目录类型替换。

所有文件按固定 128 KiB 缓冲区流式处理，不启动文件监听器或自动同步。自动发现每 15 秒广播。应用空闲时不扫描文件夹。程序只在自己的数据目录提取通信组件，退出时关闭；不安装证书，不更改系统信任、代理或防火墙规则。

## 开发与验证

需要 .NET SDK 10 和 Go 1.27.2，PowerShell 7：

```powershell
./scripts/Start.ps1
./scripts/Test.ps1
./scripts/Publish.ps1
```

脚本支持 `-Dotnet`、`-Go` 指定可执行文件路径。后端测试使用项目内隔离目录，包含两实例真实 TLS 配对和文件同步，每组设置 60 秒硬超时。测试实例只监听 `127.0.0.1`，不启用局域网发现，不申请局域网入站权限。测试材料保留在 `.test-runs`，构建材料位于 `.artifacts`，均不进入 Git。`Test.ps1 -Suite record-plans` 可单独验证方案流程；发布后用 `scripts/Verify-Release.ps1 -ArchivePath <项目内运行包路径>` 校验压缩包及隔离启动。

发布包使用英文路径：`README.md`、`ThirdPartyLicenses/`、`docs/`。界面与文档内容仍为中文，用户原有文件名称保持原样。

可执行文件参数：`--data <完整路径>`、`--ui-port <端口>`、`--port <端口>`、`--no-discovery`、`--no-browser`。默认数据目录无需手动指定；同一数据目录仅能运行一个实例。开发验证使用 `--loopback-only`，将通信端口限制到本机并禁用发现；该模式不能用于跨电脑传输。

实现说明见 [docs/DESIGN.md](docs/DESIGN.md)。验收记录见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。
