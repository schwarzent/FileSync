# FileSync 实现约定

Windows 10/11，本地浏览器界面。局域网任务支持默认单向和可选双向同步；OneDrive 中继任务支持按原始修改时间合并、手动发布和预览接收。只有点击执行才写入资料文件夹；不提供文件内容自动合并或后台自动同步。

## 数据与恢复

- 文件比较包含 SHA-256、长度、UTC 修改时间；目录内容由子项决定，目录修改时间在最后自底向上恢复，包含根目录和空目录。
- 执行前重新检查清单；所有文件流式下载并验证后才修改目标。同步期间的外部编辑导致明确失败。
- 被覆盖及删除的本机内容移动到程序数据目录的版本库，记录事务状态；支持恢复中断事务和撤销最近一次同步。可选完整备份位于用户指定目录。
- 不支持符号链接、目录联接、磁盘根目录、网络共享及相互包含的同步目录；路径检查阻止穿越、Windows 设备名及备用数据流。
- 历史记录和备份不自动删除，由使用者管理存储空间。

## 任务配置备份

- 设置页导出单个 UTF-8 JSON 文件，格式标识 `filesync-task-backup`、版本 `1`，包含导出 UTC 时间和全部 `Profile`。任务编号、局域网方向、OneDrive 路径、通用及上传／拉取过滤规则、完整备份位置均保留；不导出资料、历史、设备私钥或配对权限。
- 导入先严格解析格式及字段，再按任务编号合并；相同编号替换配置，其他现有任务保留。预览列出新增、更新和相同任务，配置哈希用于确认预览后配置未变化；导入时重新验证全部合并配置并原子保存，失败不写入部分任务。
- 导入沿用路径、模式、规则及配对校验，局域网任务要求当前设备已与备份中的原设备配对。导入不创建资料目录或触发同步；资料和版本记录保留。管理接口需本机会话认证，与同步共用互斥锁，未恢复的同步事务阻止导入。

## 独立文件记录仓库

- `Settings.RecordRepositories` 保存独立资料目录、共同仓库编号、可选记录目录及局域网设备；不依赖同步任务。加入局域网仓库时从已配对设备获取共同仓库编号；指定已存在的记录目录时读取其 `repository.json`，两端各用自己的资料路径。
- 仓库仅包含 UTF-8 JSON：`repository.json`、`snapshots/<记录编号>.json`、`heads/<设备指纹>.json`。每次手动生成读取本机资料，保存带原始时间、SHA-256、设备及 UTC 记录时间的完整清单，关联本设备上一快照和哈希，记录修改前后条目。保存历史快照后原子更新设备分支；不创建文件内容对象，不上传资料。
- 局域网通过现有双向证书认证交换两端最新记录及各自的前一快照，设备指纹必须与证书一致。接收先校验仓库、格式、快照 SHA-256、父引用、清单路径及修改列表，再保存到对应仓库。重复快照要求字节一致，禁止同编号不同内容覆盖。两端交换不扫描资料。历史快照保留；不要求每次传输完整历史链。
- OneDrive 仅中继 `.filesync-records/`，各设备分支单独保存。仓库信息或父快照尚未到齐、哈希不符时明确报错；不使用其他记录替代。记录目录与资料、备份、原有完整内容中继及程序数据目录保持分离。撤销配对仅清除仓库的设备连接，保留配置和记录。
- 只比对保存的清单，无磁盘重扫或隐式联网。按内容哈希识别一致项、两端独有条目；不同内容按原始修改时间标注较新的一端，同时间不同内容、类型及名称大小写差异标记冲突。显示各设备相对上一记录的修改；过滤规则不同时明确提示范围差异。比较不自动合并或执行文件覆盖，原有同步流程仍重新扫描校验。

## 双向同步

- `Profile.Mode` 默认为 `one-way`，可选择 `two-way`；缺失新字段的既有配置保持单向。`Share.AllowWrite` 默认关闭，只能在本机管理接口显式开启。
- 以本任务最近一条已完成版本的合并清单为共同基线；首次同步取两端独有路径的并集，同名异内容产生冲突。后续采用基线、本机与远端三方比较，传播单端修改和删除；双方内容冲突或合并后父子路径不合法时禁止执行。相同内容及目录取较晚修改时间，文件内容方向由哈希及基线确定。
- 原始两端清单、合并清单和两个方向的变化都保存在发起端计划中。接收端准备事务时验证共享授权、清单、原始文件夹状态；文件按清单顺序流式上传，逐块限制声明大小，写入前校验所有暂存文件。事务绑定配对证书身份，后续接口再次验证所属设备。
- 文件全部暂存、可选本机备份和两端状态复查完成后，先提交远端，再提交本机，最后校验两端清单。两端各自将覆盖和删除的内容移入版本库。发起端持久记录本机是否开始写入，用于区分仅远端提交与两端写入中断。
- 不提供跨设备原子事务；传输失败、提交结果不确定或后验校验失败均明确报错并保留待恢复状态。发起端恢复时查询远端真实状态，撤销已提交端或恢复中断端，再恢复本机并校验两端原始清单。恢复依赖远端在线。撤销也需要先确认两端都未出现后续修改。
- 每个同步关系由单个发起端任务维护基线。修改远端设备、共享或本机路径，或者最近完成版本为单向时，重新按首次双向规则比较。

## 文件夹选择、过滤与冲突处理

- 本机通过独立 STA 线程调用 Windows Common Item Dialog，设置 `FOS_PICKFOLDERS`，浏览器表单保留直接输入路径。选择框取消返回空结果，保留原值和表单状态；原生调用失败明确返回错误。
- `Share.IgnorePatterns` 与 `Profile.IgnorePatterns` 默认为空字符串。共享及任务支持相对路径、目录尾斜杠、根路径前导斜杠、`*`、`**`、`?` 和行注释；不支持的反向规则及字符组直接报错。规则只做排除，任务不能重新包含共享排除的路径。
- 文件清单改用 POST 携带任务规则，接收端合并共享规则后在遍历阶段跳过忽略目录，两端扫描及历史基线使用相同范围。有效规则及被跳过的路径保存在清单中；预览、事务写入、校验、备份、撤销和恢复沿用该范围。执行前及接收端提交前检查共享规则是否改变。
- 包含忽略子项的父目录加入所需清单，不能连同忽略内容被删除、改名或替换为文件。完整备份读取参与同步的内容，忽略项不读取。
- 结构冲突按最上层冲突目录分组。冲突处理接口只接受当前冲突路径和 `local`／`remote`，允许分批选择；每次生成新的预览记录，完整保留原始两端快照。选择目录采用该端整个子树，选择不存在的一端删除整个冲突范围。全部选择完成后验证父子结构，再允许执行；选择前及执行前均重新检查文件变化。
- 界面支持逐项选择、勾选批量处理、跨页全选、全部采用某端，以及批量选择后的逐项调整。选择和应用选择均不修改同步目录，最终变更仍需点击执行。

## OneDrive 中继与时间校验

- `Profile.Transport` 缺省为 `lan`，旧配置保持原有行为；`onedrive` 任务使用 `RelayPath` 和 `latest` 模式，无需配对设备。中继、资料、备份和程序数据路径必须分离。界面只读检测当前用户的 OneDrive 路径，用户选择具体中继目录；程序不读取 OneDrive 凭据、不调用 Graph、不控制客户端。
- OneDrive 扫描额外记录文件、目录和根目录的 UTC 创建时间，使用 .NET ticks 保留 100 ns 精度；局域网默认扫描及旧版本记录不新增创建时间约束。`TransactionFiles` 在清单包含创建时间时恢复该时间，目录与根目录最后恢复。接收后逐项重新扫描比较，文件系统无法精确保存时明确校验失败。
- 仓库根目录保留原始文件名、目录和文件内容，不加密。`.filesync-repo/` 保存内部记录，禁止工作区条目使用该同名顶层目录。首次提交合并仓库已有普通文件；旧版独立对象中继显式提示另选新版仓库路径，不修改旧材料。
- 格式版本 2：`.filesync-repo/snapshots/<随机编号>.json` 保存连续提交编号、设备、UTC 发布时间、带 SHA-256 的父提交引用、修改前后条目、完整原始清单和目录哈希；`.filesync-repo/objects/<SHA-256>` 保存不加密的去重历史内容。`current.json` 引用提交编号及清单字节的 SHA-256，`history.json` 为中文可读的格式化提交日志，使用明确的 ISO 8601 UTC 日期保留 100 ns 精度。读取历史沿父引用校验全部提交，检查顺序连续以及每项变化是否与前后清单一致；历史文本比较读取并验证实际历史内容。
- 通用规则与 `UploadIgnorePatterns`／`PullIgnorePatterns` 分别合并。发布只过滤本机提交范围，并保留仓库中被本端上传规则排除的条目；仓库清单不携带发布设备的过滤范围。接收只应用本机拉取规则，不要求下载被排除的内容。过滤规则不能使其他设备的仓库文件消失。
- 发布先验证已有仓库的普通文件及全部历史内容对象，合并资料并暂存新内容，重新检查工作区及仓库，然后写入持久化 `publishing.json`。应用阶段把替换内容移到 `replaced/`，从校验后的对象安装普通文件，再校验整个普通目录，生成共享日志并更新提交引用，最后将发布记录移到 `completed-publications/`。文件内容先写专用暂存路径、刷新磁盘和验证，再重命名；不使用部分复制的目标文件报告成功。
- 存在中断发布时，接收和新发布明确报错，已完成的提交历史仍可读取。显式恢复验证当前引用、前后清单、历史内容和归档，再继续完成相同提交；清单以外的外部改动会阻止恢复。恢复和文件应用期间不取消，避免报告已取消但提交已生效。中断材料和归档保留，不自动删除。
- 传输顺序、对象与清单到达云端的顺序不构成完成依据。接收验证发布记录、快照编号、格式版本、历史对象和普通文件的哈希、目录存在性、目录哈希及父子路径；不完整或损坏时不修改本机资料。原始时间以清单为准，忽略 OneDrive 写入普通文件时的传输时间。每次操作只确认本机仓库状态，无法据此宣称云端上传完成。
- 文件按原始修改时间取较新版本，独有文件保留，不自动传播删除。不同内容且同时间、类型变更及大小写结构差异产生冲突，复用逐项/批量选择界面。显式选择本机版本并成功接收后，若该子树和中继都未再次变化，后续发布可采用已确认的选择。发布同时保留已存在的较新中继内容，防止旧设备再次发布时丢失新版本。
- 中继发布不提供跨设备原子写入，需顺序发布、等待 OneDrive 完成同步；同时离线发布可能被客户端生成冲突副本。历史快照及中断材料保留，不自动清理。接收复用现有暂存、版本库、备份、恢复及撤销机制，暂存前后检查本机与中继变化。
- 路径校验仅允许 `IO_REPARSE_TAG_CLOUD` 至 `CLOUD_F` 的 Cloud Files 标记，通过打开重解析点本身读取标记。符号链接、目录联接及其他标记仍拒绝。占位内容通过正常文件读取触发 OneDrive 按需下载，客户端失败直接暴露。

## 安全

- 局域网接口仅 HTTPS，TLS 1.2/1.3。每台设备生成独立自签名证书，配对后双方按 SHA-256 证书指纹验证，每次请求要求客户端证书。
- 配对邀请包含随机 256 位一次性密钥和服务器证书指纹，5 分钟过期；通过可信渠道在两台设备间复制，勿发给无关人员。
- 私钥通过 Windows 当前用户 DPAPI 加密，不安装系统信任证书。使用 Go 标准库 TLS 进程避免 Windows Schannel 对内存私钥的限制，私钥经匿名管道传递，明文不写入磁盘。该进程嵌入主程序，仅在程序数据目录提取运行，父进程管道关闭后退出。撤销配对后立即禁止该设备访问。
- TLS 进程与业务进程仅经回环接口通信，独立随机凭据认证每次内部请求；远端不能注入设备身份头或调用本机管理 API。
- UDP 广播只发现设备，不能授权访问；发现信息不作为证书信任依据。
- 本地管理界面只监听回环地址，校验 Host、Origin 与会话请求头，远端 HTTPS 端口不提供管理 API。
- 源文件夹默认只允许已配对设备读取；启用双向写入后接受绑定共享的文件事务，不暴露任意远端路径。

## 资源

无文件监听器、无自动扫描。设备发现低频广播；扫描单文件流式哈希，传输顺序执行，缓冲区 128 KiB。任务全局互斥，预览保存在磁盘，HTTP 客户端和文件流及时释放，退出时取消发现与传输。
