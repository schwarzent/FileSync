# FileSync 实现约定

Windows 10/11，本地浏览器界面。每条同步任务支持默认单向和可选双向同步，只有点击执行才写入文件夹；新增、覆盖、删除及类型变更均先预览。不提供文件内容自动合并或后台自动同步。OneDrive 中继是后续方向，当前不实现。

## 数据与恢复

- 文件比较包含 SHA-256、长度、UTC 修改时间；目录内容由子项决定，目录修改时间在最后自底向上恢复，包含根目录和空目录。
- 执行前重新检查清单；所有文件流式下载并验证后才修改目标。同步期间的外部编辑导致明确失败。
- 被覆盖及删除的本机内容移动到程序数据目录的版本库，记录事务状态；支持恢复中断事务和撤销最近一次同步。可选完整备份位于用户指定目录。
- 不支持符号链接、目录联接、磁盘根目录、网络共享及相互包含的同步目录；路径检查阻止穿越、Windows 设备名及备用数据流。
- 历史记录和备份不自动删除，由使用者管理存储空间。

## 双向同步

- `Profile.Mode` 默认为 `one-way`，可选择 `two-way`；缺失新字段的既有配置保持单向。`Share.AllowWrite` 默认关闭，只能在本机管理接口显式开启。
- 以本任务最近一条已完成版本的合并清单为共同基线；首次同步取两端独有路径的并集，同名异内容产生冲突。后续采用基线、本机与远端三方比较，传播单端修改和删除；双方内容冲突或合并后父子路径不合法时禁止执行。相同内容及目录取较晚修改时间，文件内容方向由哈希及基线确定。
- 原始两端清单、合并清单和两个方向的变化都保存在发起端计划中。接收端准备事务时验证共享授权、清单、原始文件夹状态；文件按清单顺序流式上传，逐块限制声明大小，写入前校验所有暂存文件。事务绑定配对证书身份，后续接口再次验证所属设备。
- 文件全部暂存、可选本机备份和两端状态复查完成后，先提交远端，再提交本机，最后校验两端清单。两端各自将覆盖和删除的内容移入版本库。发起端持久记录本机是否开始写入，用于区分仅远端提交与两端写入中断。
- 不提供跨设备原子事务；传输失败、提交结果不确定或后验校验失败均明确报错并保留待恢复状态。发起端恢复时查询远端真实状态，撤销已提交端或恢复中断端，再恢复本机并校验两端原始清单。恢复依赖远端在线。撤销也需要先确认两端都未出现后续修改。
- 每个同步关系由单个发起端任务维护基线。修改远端设备、共享或本机路径，或者最近完成版本为单向时，重新按首次双向规则比较。

## 安全

- 局域网接口仅 HTTPS，TLS 1.2/1.3。每台设备生成独立自签名证书，配对后双方按 SHA-256 证书指纹验证，每次请求要求客户端证书。
- 配对邀请包含随机 256 位一次性密钥和服务器证书指纹，5 分钟过期；通过可信渠道在两台设备间复制，勿发给无关人员。
- 私钥通过 Windows 当前用户 DPAPI 加密，不安装系统信任证书。使用 Go 标准库 TLS 进程避免 Windows Schannel 对内存私钥的限制，私钥经匿名管道传递，明文不写入磁盘。该进程嵌入主程序，仅在程序数据目录提取运行，父进程管道关闭后退出。撤销配对后立即禁止该设备访问。
- TLS 进程与业务进程仅经回环接口通信，独立随机凭据认证每次内部请求；远端不能注入设备身份头或调用本机管理 API。
- UDP 广播只发现设备，不能授权访问；发现信息不作为证书信任依据。
- 本地管理界面只监听回环地址，校验 Host、Origin 与会话请求头，远端 HTTPS 端口不提供管理 API。
- 源文件夹默认只允许已配对设备读取；启用双向写入后接受绑定共享的文件事务，不暴露任意远端路径。

## 资源

无文件监听器、无自动扫描。设备发现低频广播；扫描单文件流式哈希，传输顺序执行，缓冲区 128 KiB。任务全局互斥，预览保存在磁盘，HTTP 客户端和文件流及时释放，退出时取消发现与传输。
